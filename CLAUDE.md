## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`.  The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the lobby (`LOBBY`, `CLIMB`, `NATURE`, `STANDS`, `BASES`, `climbY`, `SPAWN`, `SPAWN_FACING`), `RUN`, `TRAIN`, `WEIGHTS`, `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> lighting, lobby (`world.js`) + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, lobby effects, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Lobby**: `world.js` `createWorld(scene)` assembles it, `worldColliders()` adds the arena and climb collision. All layout, palette and sample data is in config. `terrain.js`: baseplate floor, the four walls and stepped hills as one height field of columns (green lip over purple brick, world-space UVs, two draw calls); `climbY(z)` is the height of the climb. `climb.js`: real stairs, the scrolling slide, rails, gate, YOUR BEST marker, hillside + trimesh collider, forest. `nature.js`: pines, cube trees, oaks, mushrooms, hedges. `stands.js`: shop, sell, T-Rex eggs, jellyfish, portal, gifts, paw coin, blue boards. `bases.js`: the four plots along the south wall (fences, pets, signs, strength and upgrades pads, bystanders). `pets.js`: voxel models. `voxel.js`: `Blocks` merges boxes into one mesh, `voxelGeometry` greedy-meshes ellipsoids and boxes, so nearly all static props are one draw call. The plots' owners, rates and pets are sample data copied from the reference game; nothing in the lobby has game rules yet.
- **Climb run**: `climbRun.js` is the game loop of the stairs, tuned by `RUN` in config (tiers/checkpoints included). Stepping on the stairs sets `player.drive` (a tick callback that replaces the controller; any `resetPlayer` clears it, which is how a respawn ends a run): the player carries the mystery egg up by itself, taps or Space climb faster, Auto Climb (button or C) taps for them, and strength is spent 1 per HUD metre (`RUN.metresPerS` HUD m per m of `s`). Empty bar or the summit: hop onto the slide, ride it, fly off the foot, land, then the orb hatches an egg of the highest tier passed, luck giving a chance of one tier better, into the hotbar (keys 1-8; `revealEgg` marks it in the Index). Best, strength, eggs and Auto are in localStorage until the backend save is rebuilt. `climbHud.js` + `climbHud.css` draw it (lengths are reference pixels times `--rh-u`); `body.run-active` hides the touch buttons and Index button during a run. The climb is 360 HUD m long, so tiers past Uncommon cannot be reached yet.
- **Training**: `training.js` (`TRAIN` in config). Stepping on the player's pad sets `player.drive`: they go to the centre and press the equipped weight (`ANIM.lift`, the `lift` animator input), `TRAIN.reps` a second, each paying its strength (`run.addStrength`). `climbHud.js` draws STOP TRAIN, the hand (x2 reps for `TRAIN.boostTime`, also Space) and the "+N Strength" that fly into the counter; `.training` on `body` and the HUD root hides the hotbar and Backpack. Walking away, STOP TRAIN or any `resetPlayer` ends it, and the player has to leave the pad before it restarts; the weight returns to the pad then.
- **Treadmill Shop**: `weightShop.js` + `weightShop.css` (`WEIGHTS` in config), opened by stepping on the Upgrades pad. 16 weights, one equipped, saved to localStorage. Cash buys and equips (`hud.spend`); the Robux button opens Coming Soon. `weightArt.js` holds the voxel models (long axis on X, grip at the origin) and renders each card's picture once. The equipped weight is what lies on the pad and what is lifted; `bases.setEquipped` also repaints the pad's "+N STRENGTH" and the next upgrade's price on the Upgrades sign. Pancake and up, and the Strawberry's price, are the reference's numbers; the rest are placeholders.
- **The player's plot**: `baseFarm.js` (`FARM` in config). In the owner's plot an egg in hand shows a ghost; E or the on-screen prompt places it, then hatches it near by (`discoverPet`, tab `normal`). Pets are `{ id, on }` (plain ids in old saves are migrated on load): only active ones wander the plot and join the rate, the rest wait on the bench. Rate = (`FARM.income` + active pets) times `cashMulti()` times `rebirth.multi()`, pushed to `hud.setRate` and the sign/CASH MULTI via `bases.setOwner`. Active pets pay for time away up to `offlineCap` (`hud.payOffline`). World pets are the Index models (`petArt.buildPet`). Saved in localStorage.
- **Upgrade Base**: the stone sign on the plot (`BASE_UPGRADE` in config, `upgradeSign` in bases.js, `paintUpgradeButton` in textures.js). E or the prompt near it pays for a level, each giving `slotsPerLevel` more active pets; the red ! floats over it while the player can pay. `$5M`, `0/10` and the starting 10 slots are the reference's numbers, the growth and slots per level are placeholders.
- **Pets window**: `petsWindow.js` + `petsWindow.css`, off the Pets button; the state is in `baseFarm.js` (`list`, `setActive`, `equipBest`, `slots`, `give`). EQUIP / UNEQUIP and EQUIP BEST; a full plot refuses with a toast, and a hatched pet with no slot goes to the bench. The button's ! shows while EQUIP BEST would raise the rate.
- **Rebirth window**: `rebirthWindow.js` + `rebirthWindow.css` (`REBIRTH` in config, saved to localStorage). A rebirth spends its price only and adds x1 to the cash multiplier; pets, strength and eggs stay. The button's ! shows while it is affordable. Skip Rebirth (a coin price) opens Coming Soon.
- **Daily Rewards**: `dailyWindow.js` + `dailyWindow.css` (`DAILY` in config), off the calendar button, whose red dot shows while today's reward is unclaimed. Seven days, one a day (the UTC date), the cycle restarts after day 7; only today's card is pressable. Saved to localStorage. Capybara, Bear and Whale join `PLAYTIME.pets`; `paw` rewards only count (`paws` in the save), paw coins have no use yet. Amounts are placeholders, the days' order is the reference's.
- **Sell Animals**: `sellWindow.js` + `sellWindow.css` (`SELL` in config), off the Sell tab (the Base tab while inside the plot; it no longer travels to the stall). Lists only spare pets (not on the plot) at their $/s times `SELL.mult`; Sell, Sell All, and Auto Sell (saved), which sells a pet as soon as it is spare. `farm.sell` refuses an active pet.
- **Growing Eggs**: `eggsWindow.js` + `eggsWindow.css`, off the Eggs button (the backpack stays on G and the bottom button). Lists the placed eggs (`FARM.maxEggs`, the reference's 20); CLAIM! hatches one. There is no growing time yet, so every egg is READY. Auto Hatch Eggs (a coin price) opens Coming Soon. It reuses the Pets window's frame (`petsWindow.css`).
- **Trail Shop**: `trailShop.js` + `trailShop.css` (`TRAILS` in config, 16 trails), off the Shop button. Same rail of cards as the Treadmill Shop (it reuses `weightShop.css`); cash buys and equips, the Robux button opens Coming Soon, tapping "Equipped!" takes it off. The equipped trail's multiplier scales the strength gained: `run.setStrengthMulti` (main.js) feeds `gained()` in climbRun.js for a run's gain and `addStrength` (training reps; it returns what was added for the "+N" pop). `trailArt.js` paints the card pictures on a 2D canvas, `trailFx.js` is the ribbon behind the player (one mesh, vertices rewritten per frame, rainbow cycles hue). Saved through saves.js, but there is no `SECTIONS` entry yet, so it stays in localStorage until the backend gets fields. Green, Blue, Pink, Black's Robux price, White and Rainbow are the reference's; the rest are placeholders.
- **Playtime Rewards**: `playtimeWindow.js` + `playtimeWindow.css` (`PLAYTIME` in config), off the gift button, whose badge counts what is ready and whose word falls back to the next timer. Twelve rewards on the session's clock, deliberately not saved: leaving resets them, the pets won stay. Cash rewards pay seconds of the current rate. Koala, Lion, Snail, Ostrich and Sphinx are not in the Index (`PLAYTIME.pets`, models in petArt.js); `petInfo` in baseFarm.js covers both rosters. Skip All (a coin price) opens Coming Soon. The amounts and pet rates are placeholders; the last seven timers' spacing is the reference's.
- **Lobby HUD**: `lobbyHud.js` + `lobbyHud.css` (`LOBBY_HUD` in config). Base/Play/Buy travel (`travel` in main.js), Index and the backpack (Eggs button, G) open their windows, Pets, Rebirth and the gift open theirs (`setWindows` in main.js: they need the HUD themselves), cash earns the plot's rate, in localStorage. `hud.toast` is one line over everything, windows included. Inside the plot the Base tab reads Sell (it travels to the stall; selling does not exist yet) and the offline banner shows. Shop, Event Pass, the two offers and the bottom-left icons have no system yet: they open the Coming Soon window, and their badges and prices are copied from the reference. Next Event only counts down. Hidden during a run by `body.run-active`, bar the timer; the bottom-left icons are hidden on touch (the joystick is there).
- **Effects**: `fx.js` `createBursts` is the one-shot sibling of `createParticles` (ring buffer, `emit()` at this moment); `world.bursts`. `createParticles`: GPU particles (position computed in the vertex shader from a time uniform, nothing updated per frame); add emitters, then `build()` once; `setDensity` follows `preset.particles`. Also `glowDecal` (soft light pools) and `lightCurtain`. The point lights at the gifts, eggs, jellyfish and portal are on with bloom only (`stands.setLights`); phones keep the painted glows.
- **Sky and light**: `lighting.js` sky shader with painted clouds, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `main.js` uses `LinearToneMapping` (not ACES) so the brick palette shows as painted, and the day mood's lights sum to about pi on a flat top. `textures.js` canvas painters (baseplate, bricks, foliage, slide water, cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn, I Index, E place/hatch, C Auto Climb, 1-8 hotbar, G backpack. Never bind P (CrazyGames: Boxity's pause menu).
- **Windows**: `uiWindow.js` + `uiWindow.css` are the shared shell (`createWindow`: blurred backdrop, orange studded title bar, red X, Esc via `closeTopWindow`, fitted under Boxity's toolbar via `setWindowReserved`). Every length is reference pixels times `--uiw-u`.
- **Index window**: `indexWindow.js` + `indexWindow.css` (opened with I or its HUD button; measured off a 1914x990 reference). `petIndex.js` holds what is collected, saved to localStorage until the backend save is rebuilt: hatching should call `discoverPet(tab, petId)`, reaching an egg `revealEgg(eggId)`, the economy read `cashMulti()`. `petArt.js` renders every pet and egg once to a data URL on a throwaway WebGL context, plus a silhouette for the ??? state. The roster is `INDEX` in config; only Basic Egg, Bat Egg, Parrot ($15/s), Bat and Gold's +25% come from the reference, the rest are placeholders. `npm run dev` with no save starts from `INDEX.devSeed` (the reference's 10/100); `__game.index` drives it from the console. The title font is Fredoka One (`index.html`), the same one the reference uses.
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.

## Saving, server and Bloxity integrations
- `saves.js`: every system calls `load(RUN.saveKey)` / `store(key, section)` (never localStorage directly). Sections live in memory and in localStorage namespaced by player (`key:<userId|guest|dev>`); `net.js` sends changed ones as `saveProgress` (3 s debounce, also on hide/unload) and `hydrate()` puts the server's document in first. `main.js` awaits `net.start()` (max `NET.bootWait`, 3 s without the SDK) before any system loads; a late answer is ignored so the server save is never overwritten by a stale local copy. A different player signing in later reloads the page. `petIndex.loadIndex()` runs after the load.
- `net.js`: Colyseus room `world` via `Legion.SDK.net.resolveEndpoint` (new Client per resolve, `updateRoom` after joining, `?roomId=` launches via `locateRoom`); `npm run dev` uses `NET.devServer` (`VITE_SERVER_URL`, default `ws://localhost:2567`). Token (`getToken()`) is verified by the backend.
- Daily Rewards run on the server's UTC clock (`net.daily()`, `claimDaily`): the reward is paid only after the server stores the claim; offline = cannot claim.
- Leaderboards (`LEADERBOARDS` in config, `bloxity.submitScore`, throttled): `best-climb`, `rebirths`, `strength`; Boxity draws the panel. Rewarded ads (`ADS.rewarded`, Playtime window "Watch Ad"): `showRewardedAd` -> `net.verifyAd` -> cash. Ad breaks pause the loop; `setAdScreen('lobby')` outside runs (`ADS.screens`).
- Not done: Gems purchases (excluded), drawing other players / chat bubbles / emotes, death screen (a fall just respawns).
